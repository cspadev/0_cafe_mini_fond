1 · Direction: detailed flat (B). In-game ships and hazards get the extra detail; menu icons (ship status, crates, UI card) stay exactly as today because small icons read worse with extra noise. Column A is the shipped look (ported 1:1 from src/art/shapes.ts). Add ?all to the URL to also see the earlier gloss (C) and storybook (D) experiments.

2 · Sea options

All four sit under the detailed-flat ships and hazards, are animated with plain CSS (the sea scrolls against the fleet's heading), and keep to the sea's own blue/teal range so hazard colours (storm, kraken purple, pirate navy, mermaid teal) stay the clear foreground. Use the grayscale toggle to check that nothing in the water competes with them.

Notes. B keeps the "flat colour + outline" rules but breaks the "max 3 colours per object" rule. C and D need grafika.md principle 1 (no gradients, no textures) to be rewritten. In the game each sea layer would be pre-rendered once into a tile canvas and scrolled by tcam * pps (parallax = a different speed per layer), so the extra cost is a few drawImage calls per frame. Wakes, fish, gulls and driftwood are separable and can be mixed onto any base. All options leave silhouettes and hit areas identical, so gameplay fairness (principle 6) is unaffected.
